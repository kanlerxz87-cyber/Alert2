Official scoring pending & scoring changes

This section is deliberately separate from the alert system. It runs its own poll loop, writes its own persisted store and never touches the Replay Feed's sound, queue or rows — so a change here can never disrupt an alert, and muting the alerts never stops a ruling from being logged.

Every record keeps the exact official wording observed before and after, and the official game state (score, inning, outs, count, batter, pitcher, pitch count, runners, status) captured to the second. Records survive a page refresh: the log is saved per date in this browser and, when node server.mjs is running, in data/scoring-log-<date>.json so every browser and session restores the same log. Entries are never zero-filled, guessed or silently edited: text-only payload edits are flagged for review, and a pending ruling that disappears without a final event type stays marked unresolved.

Sources: pending rulings come from the API's own event-type registry (os_ruling_pending_primary / os_ruling_pending_prior — description “Official Scorer Ruling Pending”); scoring changes are detected by snapshotting every completed play's official classification (result.eventType / result.isOut / count.outs / runners[]) on every poll and diffing it against the previous poll, because the payload carries no scoring-change marker. Attribution is by the Official Scorer, the Elias Sports Bureau or after a club review — mlb.com/official-information/scoring-changes.
